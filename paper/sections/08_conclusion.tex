\section{Conclusion}
\label{sec:conclusion}
Three conventions that evaluations of KV-cache tiering leave unstated each decide a conclusion. The tie rule
for blocks without evidence decides whether the same clairvoyant split-time reference reaches 15--20\% of
the oracle's advantage or 76--78\% (tier-only) while the fast tier is large beside the live blocks, the case LRU-K left to
a subsidiary policy in 1993. The matching rule that serving engines implement reverses a published
simulator's headline. The write path decides whether storing a block costs a request nothing or many times
its transfer time, so the additive price that tiering studies use is wrong both ways. With the three fixed,
knowing which seen blocks are dead is worth as much as knowing their whole future while the live blocks fit
in the fastest tier, a parameter-free rule recovers about half of that, none of the replayed policies that
move blocks beats a static frequency heuristic at the move prices we measured when moves block, unless remote
moves are nearly free, and reactive replacement stays within a few points of plain rules.

For whoever evaluates a memory scheduler next, the practical content is short: report the tie rule for
blocks without evidence, the matching rule and the write path, sweep every convenience choice, bill
creations as compulsory misses, and measure or bound what a move costs. The artifact implements each as a
default.
