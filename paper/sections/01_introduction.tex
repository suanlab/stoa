\section{Introduction}
\label{sec:intro}
LLM serving systems now keep the attention state of past requests, the KV cache, across a hierarchy of
GPU memory, host memory, remote memory and storage, so that a later request sharing a prefix reads it
instead of recomputing it~\cite{qin2024mooncake,gao2024cachedattention,F5_liu2025lmcache,zhang2026polarkv}.
Which tier holds which block is a buffer-management decision~\cite{pan2025dbperspective}, and like every
such decision it is evaluated by replaying a trace: let a policy observe part of it, place blocks, and bill
the rest against a hindsight reference. This paper is about what that evaluation has to fix, because on
production KV traces the choices it makes silently decide what it reports. We measure three such
conventions (\Cref{fig:conventions}), and each reverses a conclusion (one of them our own earlier headline): the tie rule for blocks without evidence, the rule that decides
which cached blocks count as hits, and the write path that decides what a store costs a request.

\paragraph{The tie rule} Most blocks an evaluation shows a policy are already dead. On two production Mooncake
traces, \textbf{92.8\% and 95.0\%} of the blocks seen before the split, the request halfway through the trace,
are never read again. A clairvoyant reference gives these dead blocks and the blocks not yet created the same
belief, zero, and orders them by a tie rule, the case LRU-K left to a ``subsidiary policy''~\cite{oneil1993lruk}.
With the dead blocks first, as item order puts them, the reference reaches \textbf{20.4\% and 15.3\%} of a
hindsight oracle's advantage (tier-only actions), which suggests that a split-time policy can reach little of it;
with them last, which costs them nothing, the same reference reaches \textbf{77.8\% and 76.2\%}
(\Cref{sec:ties}). The swing holds across splits while the fast tier is large beside the live blocks, and
nearly vanishes at one GPU's worth of KV. Where it holds it decides how a result reads: the strongest learned
ranker we trained (with all actions, where it was trained) is more than half of the way to the first reference
and about a sixth of the way to the second.

What the oracle knows can be taken apart. While the live blocks fit in the fastest tier, knowing \emph{which}
seen blocks are dead is worth as much as knowing every seen block's future (\Cref{sec:ladder}). The prefix
approximates deadness: a block seen once is dead with probability 0.95 and 0.97, and a rule that parks
seen-once blocks behind new ones, with no parameters, captures 39.2\% and 43.3\% of the advantage in a static
bill, and an estimated prior for new blocks 47.0\% and 51.7\% (\Cref{sec:arrival}). Counts mislead because KV
reuse is bounded by sessions~\cite{liu2026fancyeviction}: estimators that assume independent references
overpredict a seen block's reuse 3.7 to 8.4 times (\Cref{sec:why}).

\paragraph{The matching rule} An engine reuses a block only behind its whole prefix: vLLM and SGLang stop
matching a request at its first miss. The open simulator of a recent eviction study counts a cached block as a
hit even behind a block that missed; counted the way vLLM and SGLang match a request, its headline
compute-aware policy goes from 10.4 points ahead of LRU to 19.6 points behind (\Cref{sec:matching}).

\paragraph{The write path} Evaluations bill a store, like a move, as a constant per block. Inside a serving stack
that price is wrong both ways, because what a request pays for a store depends on the connector's write path.
On a trace slice replayed into vLLM near saturation, storing every block raises median time to first token by
76\% over storing none when the store blocks the step (LMCache), and stays within run-to-run noise when the
store is asynchronous (vLLM's offloading connector); where admission leaves hits unchanged, a clairvoyant
admission rule is 31.1\% faster on the first path and within 0.3\% on the second. In SGLang, a write rule
documented to store a block on its second access stores every request that decodes a second token, and storing
at a request's completion rather than at its prefill lowers mean latency by 8.8\% at the heavier load (the
median by 17--23\%) with the same hits (\Cref{sec:contract}).

\paragraph{With the three fixed} Replayed online, plain recency does better than any arrival-time policy when
moving a block is free: a multi-tier LRU captures 84.5\% and 87.7\% (\Cref{sec:online}). On one A100 host a move
between GPU and host memory costs 0.75--1.87 times one read plus one write, at least 2.5 times the price at
which any policy that moves blocks stops paying. In an additive cost model, under every way of billing a move we
tried, none of the replayed policies that move blocks beats a static frequency heuristic on the production
traces, unless a move to the remote tier, which we could not measure, costs less than about a quarter of a read
plus a write. That holds while a move takes link time a load needs, as on our host; the free ledger bounds what
recency could gain. Reactive replacement stays within a few points of plain rules: the adaptive family (ARC,
LeCaR, CACHEUS) beats the best plain rule chosen per operating point by at most 4.6 points of Belady when
frequency remembers evicted blocks (8.5 at the tightest tier when it does not), a learned LRB does not beat ARC,
and S3-FIFO, SIEVE and W-TinyLFU stay below that per-point best everywhere (\Cref{sec:reaction}).

\paragraph{Contributions}
\begin{itemize}
  \item \textbf{(C1) Three conventions that reverse conclusions}, defined with the rest of an evaluation's
  frame (\Cref{sec:defs}) and measured: the tie rule for blocks without evidence moves a clairvoyant reference
  by 48--63 points with a pooled fast tier (\Cref{sec:evidence}); the matching rule serving engines implement
  reverses a published simulator's headline (\Cref{sec:matching}); and inside a serving stack, whether store
  admission changes latency is decided by the connector's write path, not by the additive price
  (\Cref{sec:writepath}). The tie rule decides split-time references, which none of the online KV-cache
  studies we read uses (\Cref{tab:protocols}).
  \item \textbf{(C2) Findings with the conventions fixed}, replicated on Alibaba's traces where the data allow:
  while the live blocks fit in the fast tier, deadness, not ranking, is what placement has to get right, and a
  parameter-free prefix rule recovers about half of what knowing it is worth; at the move prices we measured,
  none of the replayed policies that move blocks pays while a move takes link time a load needs, unless
  remote moves cost under a quarter of a read plus a write; and modern
  one-hit-wonder policies do not beat the best plain rule chosen per operating point
  (\Cref{sec:ladder,sec:arrival,sec:fixed}).
  \item \textbf{(C3) An artifact and a record.} Every number regenerates from public traces, on CPU except the GPU
  timings, and a checker fails on drift; the thirty-one defects that each produced a plausible number on the way here,
  four of them retracted claims, are catalogued with the control that catches each (\Cref{sec:lessons}),
  as a record of one project rather than an estimate of how often such defects occur.
\end{itemize}
