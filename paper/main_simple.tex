\title{\textbf{STOA: A Learned Control Plane for Tiered Agent Memory}\\
\large Where, How, and When to Remember, under a Budget}
\author{STOA Project\\ Semyung University\\ \texttt{suanlee@semyung.ac.kr}}
\date{}

\begin{document}
\maketitle

\begin{abstract}
LLM agents increasingly depend on external memory, but the single decision that governs it---for each
memory item, in what \emph{representation} (plaintext, vector, graph, latent/KV, parameter), on which
\emph{storage tier} (GPU, CPU, disk, remote), and \emph{when} to (re)materialize it (online vs.\
sleep-time)---is today split across three communities that each optimize one axis and fix the others.
Memory-OS work migrates representations by heuristic; RL memory managers edit content over a single
representation; KV-cache tiering places bytes to cut miss-rate, ignoring task utility. We argue these
axes are \emph{coupled} and form one \textbf{budget-constrained scheduling problem} that is learnable. We
present \textbf{STOA}, a learned control plane that decides representation $\times$ tier $\times$ timing
jointly, per item, under latency/cost/token budgets, as a single budget-constrained MDP exposing one
serve-time \textbf{$(L,C,B)$} knob. STOA factors the policy over a GNN of the memory graph and
warm-starts it by imitating a Belady oracle. On a trace-calibrated tiering simulator and the LoCoMo
benchmark we show early evidence---and a clarifying negative result that pinpoints, and then resolves, the
need for a \emph{sequential, occupancy-aware} formulation---then lay out an agenda for a unified,
budget-constrained, safety-aware memory runtime.
\end{abstract}
